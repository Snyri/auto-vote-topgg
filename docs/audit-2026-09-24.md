## Changes

- **Authentication readiness:** recognize managed interstitial titles/containers and require recognizable top.gg UI after a detected challenge before probing the session. Waits only observe the page, without extra navigation. Widget disappearance is no longer logged as verified access. Public Vote navigation links cannot authenticate a session.
- **Bounded session request:** a browser AbortController limits fetch/body processing to 12 seconds; an outer asynchronous timeout also covers a stalled browser connection. Malformed probe results cannot authenticate an account.
- **Partial results:** a later bot exception preserves earlier completed votes. Account-wide authentication/protection failures on a retry apply only to pending bots. Missing results become explicit failures. Duplicate bot IDs are collapsed, and IDs must use ASCII digits.
- **Cleanup:** unexpected teardown errors cannot overwrite completed voting results. A profile is still deleted after forced termination succeeds. Error screenshots are removed even without Telegram configured.
- **Scheduler:** preserve accepted run IDs and deadlines across dispatch cycles, query a known run directly when lists regress, and respect the later of a failed-run defer deadline and a prior successful future deadline. Refreshes are throttled. Artifact downloads have a streaming size cap and require exactly the expected ZIP entry.
- **Workflow:** serialize voting across branches, propagate artifact/infrastructure errors independently of the Python exit status, validate recovery depth strictly, and read bounded recovery ZIPs without extracting paths.
- **Dependency audit:** follow bounded OSV pagination; reject malformed, incomplete, or unsupported audit inputs. All 12 pinned packages passed a live OSV query. Dependency and Action versions were retained.
- **Documentation:** replace obsolete architecture images with a maintained Mermaid flow, correct multiline local configuration examples, and remove inaccurate assertions that branch protection is enforced. GitHub reported `master` unprotected and no repository rulesets.

The follow-up distinguishes a full-page challenge still present at the timeout from an embedded widget. Persistent interstitials use `blocked` and the existing bounded recovery policy; standalone CAPTCHA behavior is preserved. The distinction applies to cookie/OAuth authentication and all five challenge checks around voting. A post-click block explicitly reports the vote outcome as unverified.

Regression tests cover the previous failure, real embedded JavaScript against controlled page fixtures, authentication/OAuth propagation, all five voting phases, and unchanged recovery limits. This corrects result classification; it does not demonstrate that Cloudflare will accept the next request.

## Follow-up: restore authentication paths restricted by the audit

[Runs 142](https://github.com/Snyri/auto-vote-topgg/actions/runs/36056842024) and [143](https://github.com/Snyri/auto-vote-topgg/actions/runs/36057245802) each exhausted four 30-second challenge waits across two browsers, without reaching a session probe or clicking Vote. The one fresh-workflow recovery operated as intended. In contrast, the last successful [run 138](https://github.com/Snyri/auto-vote-topgg/actions/runs/35974310817) progressed past widget disappearance, sometimes received a 403 session response, and eventually reached the vote page. Chrome was the same version in these runs. The user also confirmed that the vote page opens normally in their usual browser; this does not isolate runner IP reputation as the cause.

The audit had introduced overly restrictive authentication paths: a residual interstitial title or container could keep the widget loop active and hide a usable Vote control; an unknown DOM state after verification could no longer fall back to the session endpoint. Regression fixtures reproduce these failures in the audit code, including a valid session being rejected without checking it. They do not establish the exact DOM of the failed runs.

This follow-up selectively restores the pre-audit widget detection and application-control precedence, and restores the session-probe fallback after bounded DOM settling. HTTPS/origin/loading checks, request timeouts, strict session-response validation, partial-result preservation, cleanup and scheduler fixes remain. A failed session probe still reports blocked; a dispatched click still does not count as verified access or a successful vote.

Challenge diagnostics now record only fixed boolean signals and a loading-state enum at detection, click failure and timeout. They distinguish present versus visible interstitial containers, visible application controls and token presence without logging page text, URLs, account data, or token values. Collection has a two-second limit and cannot replace the original result on failure. The verification-click log now explicitly says that neither target matching nor acceptance is confirmed by the library call.

The restored paths are checked with JavaScript fixtures and session-response tests; diagnostics additionally have privacy, malformed-response and cancellation tests. A successful live workflow remains necessary to confirm recovery in the real environment.
